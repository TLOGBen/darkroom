# darkroom App 外殼 設計審查（2026-10-04）

- 審查對象：`darkroom_app/static/index.html`、`app.css`、`app.js`（加上 `server.py`、`sliders.py`、`presets.py`、`preview.py` 決定介面行為的部分）
- 方式：用 8766 埠另開一份 App（`python -s -m darkroom_app --port 8766`），在 Chrome（隔離 context）實際操作：開照片、展開 preset 樹、點 preset、強度拉到 150%／50%、拖滑桿、展開所有區塊、按住 `\` 看原圖、← 換上一張、搜尋、把視窗縮到 1100 和 820 寬。測試照片用 `prototypes/llm-pick-experiment/photos/`（sunset_kite、street_rain）。
- 只審查，沒改程式碼。截圖都在同一個資料夾。
- 數字來源：preset 統計是在頁面裡從 `/api/presets` 算的；曲線統計是用 darkroom 函式庫 `load_preset` 逐一讀 1466 個 xmp 算的。

## 整體印象

骨架對了：三欄（preset／預覽／滑桿）、Lightroom 的區塊順序、暗色、拖動 15～190 ms 回圖，基本流程「點 preset → 調強度 → 微調」走得通。問題主要在三個地方：

1. **會無聲弄丟或扭曲使用者的調整**（換 preset 清掉微調、沒有復原、強度和微調疊在一起時數字跳動）。
2. **介面沒誠實反映 preset 做了什麼**（點曲線看不到、超過範圍被夾住看不出來、警告列太常出現而且是英文鍵名）。
3. **版面寬度寫死**，視窗一縮就壞，也沒替之後的照片庫、preset 庫留位置。

## 現在就該修

依嚴重程度排序。

### 1. 換 preset 會清掉所有微調，而且沒有復原【嚴重】

- 位置：`app.js` `selectPreset()`，`st.strength = 100; st.tweaks = {};`；全站沒有 Ctrl+Z／歷史紀錄。
- 情境：調了曝光、對比之後想「換別的 preset 比比看」，一點就全部歸零，強度也被打回 100%。Lightroom 的用法正好是一邊瀏覽 preset 一邊保留自己的修改（preset 只覆寫它有設定的欄位），而且有 Ctrl+Z 和歷史面板。這是 LR 使用者最容易踩到、損失最大的一個。
- 建議：
  - 換 preset 時保留微調（微調本來就是差值，留著就好）；強度可保留目前值或記住每個 preset 上次的強度。
  - 至少先做 Ctrl+Z／Ctrl+Shift+Z（記錄 preset、強度、微調的快照，拖滑桿一次只記一筆）。
  - 如果決定換 preset 一定要清微調，清之前用提示列給「復原」按鈕。

### 2. 換照片時調整會原封不動帶到下一張，畫面上沒有任何提示【嚴重】

- 截圖：`07-prev-photo-carries-edit.png`（在 sunset_kite 套 16 Cinematic 16、強度 150%、微調 2 項後按 ←，street_rain 直接套上一模一樣的設定）。
- 位置：`app.js` `openPhoto()`／`step()` 不碰 `st.presetId`、`st.strength`、`st.tweaks`。
- 問題：LR 的每張照片各有自己的設定；這裡是「全域一份設定」。之後照片庫要「每張自動記住修改」時，現在的行為會讓使用者以為已經記住，回到前一張卻發現是新設定。
- 建議：在照片庫做出來前，二選一並讓它看得見：(a) 換照片時回到「未選＋100%＋無微調」；(b) 保留但在上方顯示「沿用上一張的設定」。長期就是每張照片各自一份狀態。

### 3. preset 的點曲線完全看不到【嚴重】

- 數字：1466 個 preset 裡有 **1235 個**帶非直線的點曲線（`ToneCurvePV2012`、紅綠藍各通道）。渲染時有套（`preview.effective_params` 會帶 `base.curves`），但右欄「曲線」只有四個參數式滑桿，套了 preset 後都還是 0（`03-preset-banner.png`、`05-hsl-grade-effect.png`）。
- 問題：使用者看到「曲線全是 0」會以為 preset 沒動曲線，實際上大部分的色調都來自它。LR 的色調曲線面板一定會畫出曲線。
- 建議：在「曲線」區塊上方畫一張唯讀的小曲線圖（RGB＋各通道疊色），有強度時畫套強度後的曲線。可編輯的曲線之後再做。

### 4. 強度超過 100% 時數值被夾住，滑桿看不出來；微調數字也會跟著跳【高】

- 截圖：`04-strength150-tweaks.png`。
- 實測：16 Cinematic 16 強度 150% 時，對比的 preset 值是 −112、亮部是 −127，滑桿顯示成 −100（`clampKey`，後端 `clamped()` 也一樣夾住）。我把對比拉到 −100，系統記成「微調 **+12.5**」——使用者往負的方向拉，卻得到正的微調。強度再改成 50%，同一列顯示 −25；曝光拖到 +0.60 後，強度改 50% 變成 +0.78。
- 問題：LR 使用者的心智模型是「滑桿上的數字就是最終值」。現在的「preset × 強度＋差值」模型可以保留，但介面要把它講清楚，不然每次動強度，已經手動對好的數值都會偏掉。
- 建議：
  - 被夾住的滑桿標出來（例如數字後面加「上限」或改色，tooltip 寫「preset × 150% = −127，已到下限」）。
  - 決定一種行為並在介面上說清楚：使用者手動拉過的滑桿要「釘住最終值，不跟強度走」（比較符合 LR 習慣），或維持差值但在列上同時顯示「preset 值｜你的微調」。我建議前者：微調過的項目改存成絕對值，強度只影響沒動過的項目。
  - 強度條在 100% 的位置加刻度，超過 100% 的那一段換個顏色，表示「放大 preset」。

### 5. 「無法套用」警告太常出現，而且寫的是英文鍵名【高】

- 數字：1466 個 preset 裡有 **1199 個**在樹上掛 ⚠。最常見的原因是 `ColorNoiseReduction`（855）、`LuminanceSmoothing`（755）、`Temperature`／`Tint`（各 321）、`SharpenDetail`（223）。
- 截圖：`03-preset-banner.png`，警告列寫「…無法套用：Temperature、Tint、SharpenDetail、LuminanceSmoothing、ColorNoiseReduction」。
- 問題：八成的 preset 都有 ⚠，這個標記等於沒有資訊；英文 crs 鍵名對使用者沒意義；降噪這類對 JPEG 預覽幾乎沒影響的項目，和「白平衡沒套」（色調會明顯不同）被放在同一級。另外，警告列放在預覽圖上方，會依 preset 出現或消失，換 preset 時整張圖會上下跳 26～90px（820 寬時折成四行，見 `10-width-820.png`）。
- 建議：
  - 分兩級：**會改變觀感的**（Temperature／Tint 絕對白平衡、CameraProfile、HDR、遮罩……）才在樹上標 ⚠、顯示警告列；**細節類**（降噪、銳化細節、鏡頭校正）只在 tooltip 或細節區塊裡用灰字提一句。
  - 警告列用中文名稱（色溫、色調、雜色減少、明度平滑……），對應 LR 中文介面用語，可以加「詳細」展開原始鍵名。
  - 警告列改成固定高度的一行（放在預覽工具列裡，或疊在圖的上緣），不要把預覽往下推。
  - 註：警告列的句型是合約 B11 的逐字常數，改寫法要一起改合約。

### 6. 視窗變窄就壞掉【高】

- 截圖：`09-width-1100.png`、`10-width-820.png`。
- 位置：`app.css` `#editor { grid-template-columns: 280px minmax(0,1fr) 360px }`，上方列 `#status { min-width: 190px }`、`#position { min-width: 120px }`。
- 1100 寬：上方狀態文字折成兩行、檔名被截成「street_rai…」。
- 820 寬：預覽只剩約 180px 寬，強度滑桿縮到看不見（只剩一顆圓點），「目前 preset」折成三行，上方列的狀態文字超出畫面。
- 建議：
  - 左右欄可拖寬度，並可收合（LR：F7／F8 收左右欄、Tab 全收）；寬度低於約 1200 時左欄自動收成一條。
  - 預覽區設最小寬度（例如 400px），不夠時優先收左欄。
  - 上方列的後端毫秒數移到狀態列或 tooltip；檔名的優先權高於狀態文字。

### 7. preset 樹和區塊標題不能用鍵盤操作；不能用方向鍵一個一個試 preset【高】

- 位置：`.tnode` 和 `.acc > .ah` 都是沒有 `tabindex` 的 `div`（頁面上 0 個可聚焦）；Tab 鍵會依序經過 40 幾個滑桿才走完一輪。
- 問題：在 LR 裡試 preset 的主要方式是滑鼠移過 preset（左上導覽器即時預覽）或上下鍵一個一個看。這裡只能用滑鼠逐一點擊，1466 個 preset 試起來很累。
- 建議：
  - preset 樹做成真正的 tree（`role="tree"`／`treeitem`、roving tabindex）：↑↓ 移動並**直接套用**（latest-wins 的預覽管線已經撐得住）、←→ 收合／展開、Enter 套用。
  - 搜尋：`Ctrl+F` 或 `/` 跳到搜尋框，Esc 清空，從搜尋框按 ↓ 進入結果。
  - 區塊標題改成 `<button aria-expanded>`。

### 8. 搜尋找不到資料夾名稱，結果沒有標出符合的字【中】

- 截圖：`08-search.png`。
- 實測：資料夾是中文（電影、顏色、風格…），preset 名稱幾乎都是英文（1466 個裡 1203 個純英文）。搜「電影」→ 0 個；搜「cinematic」→ 65 個；搜「B&W」、「bw」→ 0 個。
- 位置：`renderTree()` 只比對 `p.name`。
- 建議：同時比對 `group`（「電影」就會列出整個資料夾）；多個關鍵字用空白分開、全部要符合；符合的字加底色；結果依資料夾分組顯示而不是攤平。

### 9. 滑桿可讀性：雙向滑桿從最左邊開始填色，色相滑桿沒有顏色【中】

- 截圖：`02-opened.png`、`05-hsl-grade-effect.png`。
- 位置：`input[type=range]` 只靠 `accent-color: var(--accent)`，用的是瀏覽器預設樣式。
- 問題：
  - 範圍 −100～+100 的滑桿，在 0 的時候藍色已經填滿到一半，看起來像「已經調了 50%」，一整欄藍條也很搶眼，壓過照片本身。LR 的滑桿是細灰軌＋小三角，不填色，只看把手位置。
  - HSL 的 8 色和顏色分級的色相（0～360）沒有色帶，只能看數字猜顏色；LR 每條 HSL 滑桿都有漸層，顏色分級是色輪。
  - 滑桿軌道只有 169px（360px 欄寬減掉 92px 標籤、46px 數字），−100～+100 每 1 單位不到 1px，精細調整很難。
- 建議：
  - 自己畫滑桿：細軌（約 2px，灰）、雙向滑桿在中點畫刻度、只從中點往把手方向填一點淡色（或不填）、把手小一點。
  - HSL 色相列用該顏色從左到右的色相漸層，飽和度列用灰→該色，明度列用黑→該色；顏色分級的色相用整條 0～360 色相環漸層。
  - HSL 分頁加「全部」（LR 有 All），一次看三組。

### 10. 數值不能直接輸入，沒有微調倍率【中】

- 位置：`.sl .v` 是 `span`。
- 問題：LR 使用者習慣點數字直接打值、在數字上滑鼠拖曳、把滑鼠停在滑桿上用 ↑↓ 微調（Shift 放大十倍）。
- 建議：數字改成可點擊編輯的輸入框（Enter 確認、Esc 取消）；聚焦滑桿時 Shift+方向鍵十倍步長；按住 Alt 拖動時減速。

### 11. 已調整項目的標示：只看得出「你的微調」，看不出「preset 改了什麼」；tooltip 會過期【中】

- 截圖：`04-strength150-tweaks.png`（曝光、對比標成橘色＋「●」，區塊標題有「● 微調 2 項」，這部分做得好）。
- 問題：
  - preset 有改動的滑桿和完全沒動的長得一樣，13 個基本滑桿裡哪幾個是 preset 動的要逐一看數字。
  - **bug**：強度從 100% 改成 150% 後，沒動過的滑桿 tooltip 還寫「preset × 強度 100% = −85」——`refreshSliderValues()` 只更新值，沒重算 `row.title`。
  - 「雙擊＝還原」只寫在 tooltip；LR 是雙擊標籤還原，這裡只有雙擊滑桿本身有效，雙擊標籤沒有反應。
- 建議：preset 有設定的滑桿，在軌道上用一個小記號標出 preset 值（微調後還能看到原本在哪）；修掉 tooltip 過期；標籤也支援雙擊還原；區塊標題的「微調 N 項」旁加一個還原這個區塊的按鈕（LR 的區塊開關／重設）。

### 12. 強度區的細節【中】

- 截圖：`02-opened.png`（顯示「100%」數值旁邊又有一顆「100%」按鈕）。
- 問題：
  - 兩個「100%」並排，不知道哪個是值、哪個是按鈕。
  - 沒選 preset 時強度滑桿照樣能拖，但拖了沒有任何效果（`baseVal` 在沒 preset 時直接回預設值）。
  - 強度條在預覽下方、目前 preset 名稱跟它一起放；和左邊點的那一列距離最遠。
- 建議：按鈕改成「重設」或 ↺ 圖示；沒選 preset 時強度停用並顯示「先選一個 preset」；數字可直接輸入；強度條上 100% 處加刻度（見第 4 點）。

### 13. 暗色主題的對比【中】

## 之後再做

### A. 為 preset 庫和照片庫預留版面

建議的版面（接近 LR 的 Develop 模組，LR 使用者不用重新學）：

```
┌─ 上方列：開啟資料夾｜照片名稱 1/10｜（右）復原 重做 ───────────────┐
├──────────┬──────────────────────────────┬──────────────┤
│[Preset|相簿]│        預覽                    │ 色階分布圖     │
│ 分頁       │                              │ ─────────── │
│ 搜尋＋篩選  │                              │ 強度（套用中的 │
│ ★ 最愛    │                              │  preset 名稱）│
│ 資料夾樹   │                              │ 基本／曲線…    │
│           │                              │              │
│[＋匯入][另存]│                              │[複製][貼上][重設]│
├──────────┴──────────────────────────────┴──────────────┤
│ 底片列：這個資料夾的縮圖（有修改的標記）                           │
└──────────────────────────────────────────────────────┘
```

- 強度移到右欄最上方、緊接在 preset 名稱下面：「選了什麼、套多少、再怎麼微調」從上到下一條線。預覽下方空出來給底片列。
- 左欄分頁：「Preset」與「相簿資料夾」，同一個位置，不同時佔空間。
- preset 列：滑過顯示 ★（最愛）、右鍵選單（改名、移動、刪除）；樹頂端固定一個「★ 最愛」與「最近使用」。
- 右欄底部固定「複製設定／貼上設定／重設」，對應 LR 的 Copy／Paste／Previous／Reset。
- 底片列：縮圖上有「已修改」標記；選多張後「套用目前設定」。
- 這些都不需要現在做，但第 6 點（欄寬可拖、可收合）和把強度移到右欄，最好現在就照這個方向改，之後才不用再搬一次。

### B. 開照片的方式

目前要手動貼路徑（`01-empty.png`）。照片庫做出來前，至少支援把檔案拖進視窗，或「開啟資料夾」用原生對話框（後端已經會列同資料夾的檔案）。

### C. 預覽放大與色階分布圖

- 預覽固定最長邊 1280／1500（`photo-size` 顯示「預覽 1000×1500」），看不到銳化、顆粒、雜訊的效果。之後加 1:1 放大（點一下放大、空白鍵拖曳，對應 LR 的 Z）。
- 右上加色階分布圖，LR 使用者調曝光、白色、黑色時會一直看它。

### D. 可編輯的曲線、顏色分級色輪

第 3 點的唯讀曲線之後，再做可拖點的曲線；顏色分級改成三個色輪＋混合／平衡滑桿（LR 的樣子）。

### E. preset 試用的進階方式

滑鼠停在 preset 上就預覽（不點擊），離開就回到目前套用的那個；或 3×3 縮圖格一次比較九個 preset（底片列可以重用）。

### F. 狀態列

「預覽：已更新（後端 23 ms，往返 28 ms）」是開發用資訊，正式使用時移到狀態列角落或除錯模式；一般時候只在出錯或算圖超過 0.3 秒時顯示。

## 做得好的地方（保留）

- 三欄配置、區塊順序、區塊名稱都對得上 LR 中文版，熟悉的人一看就懂。
- 收合的區塊標題仍顯示「● 微調 N 項」，微調過的滑桿標成橘色並有 ↺ 按鈕，「還原單項」和「還原全部」都有。
- 預覽管線只送最新的參數（不排隊），快速拖動時回圖穩定；換圖時先載好再替換，不會閃。
- 展開的區塊記在 localStorage，下次打開維持原狀。
- 拖滑桿時不重畫整個面板，只更新該列，手感順。
