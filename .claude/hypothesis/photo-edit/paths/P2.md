# P2　清除編輯時，把 AI 代理剛存的編輯刪掉，連「上一份」都沒留

你在 App 按「清除編輯」的同時，AI 代理剛好存了一份編輯；清除照樣把檔案刪掉，但它先前讀到的是「沒有編輯」，所以什麼都沒留，那份編輯消失，也取不回來。

- **不成立的規則**：R2　被清掉的編輯，一定先留成「上一份」。
- **傷害**：剛存的修圖整份消失，「取回上一份」也救不回來。
- **發現類型**：bug
- **圖**：diagrams.html 的最後一張

## 劇本

1. 這張照片目前沒有編輯。
2. 你在 App 按「清除編輯」：程式讀到「目前沒有編輯」。— `darkroom_app/services/photo_library.py:358`
3. 就在這時候，AI 代理透過 MCP 存了一份編輯 A。— `photo_library.py:351`
4. 清除繼續：編輯檔存在，所以往下做。— `adapters/persist/edit_store.py:99`
5. 要留成上一份的，是第 2 步讀到的「沒有」，所以什麼都不留。— `edit_store.py:101`
6. 刪掉編輯檔：A 消失。— `edit_store.py:105`

## 每一步都走得到嗎

1. 是，照片可以沒有編輯。
2. 是，`clear_edit` 先讀目前編輯。
3. 是：同 P1 第 5 步，寫入沒有鎖。
4. 是，`remove` 檢查的是當下的檔案，不是第 2 步讀到的內容。
5. 是，`keep` 是第 2 步傳進來的 `None`，`if keep is not None` 跳過。
6. 是，直接刪檔。

## 給讀者的探針

- hunt：`edit_store.py:105` 刪檔時，被刪的內容是不是 `photo_library.py:358` 讀到、並且留成上一份的那一份？
- prove-it 強制順序：讓 `clear_edit` 在 `:358` 讀完之後暫停，期間從 MCP 存一份編輯，再讓清除繼續；之後照片應該要有「上一份」可取回，實際沒有。
